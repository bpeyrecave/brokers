# Every Day I'm HODLing

_Victor & Berta try to become brokers on a P2 salary._

A small dashboard for two friends who are paid in USD but live and spend in EUR. Every month you can either let your
organization auto-convert your salary at the rate it sets around the 13th, or manage the USD → EUR conversion
yourselves. This dashboard exists to answer one practical question: **is actively timing the conversion actually
worth meaningful money, or is the difference small enough that you should just automate it and stop thinking about
it?**

It is not a trading tool, not investment advice, and it does not predict future exchange rates.

## What's in here

1. **Current rate & trend** — today's USD → EUR rate plus 1/7/30-day change, framed as "how many euros do I get for
   my dollars" (a *higher* number is good for you).
2. **Calculator** — type any USD amount (defaults to $5,000, with $1k/$3k/$5k/$10k presets) and see the EUR value
   everywhere on the page update live.
3. **Time comparison** — the same amount valued today, yesterday, 7 days ago, 30 days ago, and on the 13th of this
   month (your organization's benchmark), with the euro difference for waiting.
4. **"You vs. the 13th"** — a dedicated benchmark card comparing today's rate against the organization's rate, in
   euros and percent, with a plain-language sentence.
5. **Interactive historical chart** — 1W/1M/3M/6M/YTD/1Y ranges, a dashed marker on every 13th, current-rate dot,
   high/low for the visible range, and a hover tooltip showing the date, the raw rate, and your chosen amount's EUR
   equivalent.
6. **"What if I had exchanged?"** — pick any past date (or two dates) and compare.
7. **"Should I exchange today?"** — a decision-support card based on transparent historical percentiles (today's
   rate vs. the last 30/90 days), never a market prediction. The methodology is explained in an info tooltip.
8. **☕ Today's FX Brief** — a short, plain-language daily summary of what's moving USD/EUR, generated by an LLM with
   web search. Explicitly separates what markets expected vs. what happened vs. how the rate reacted, and never
   forecasts future rates. If it fails to generate, the rest of the dashboard is unaffected.
9. **What to watch** — an upcoming-events timeline (Fed/ECB decisions, inflation & employment data, etc.) with a
   HIGH/MEDIUM/LOW relevance tag and a one-line explanation for each.
10. **"Was the headache worth it?"** — log your real conversions (amount, date, rate, EUR received, fees, note) and
    compare your actual results year-to-date against simply converting on the 13th every time.
11. **Market rate vs. Wise** — since Victor & Berta always convert through [Wise](https://wise.com), that's the
    default: Wise uses the real mid-market rate (no hidden markup) and charges a transparent fee instead, so the
    toggle deducts a fee from every "what do I actually get" figure instead of touching the rate. The fee is modeled
    in two marginal tiers, since Wise's real percentage fee gets cheaper as the amount grows — a higher percentage
    on the portion up to an editable threshold, a lower one above it — plus a small flat fee. A "Market rate" option
    is still there for comparison. Defaults approximate a typical USD→EUR bank-funded Wise transfer — edit the fee
    fields to match your actual Wise quote.
12. **Smart extra metrics** — 30/90-day averages, best/worst rate this month, distance from the monthly high, and
    what perfect timing would have been worth vs. the 13th — mostly to show that chasing the "perfect" day usually
    isn't worth obsessing over.
13. **HODLing since the 13th** — a small, playful counter for how many days you've been sitting on this month's
    balance and what that patience is currently worth.

## Data sources

| Data | Source | Why | Needs a key? |
|---|---|---|---|
| Current & historical USD/EUR rates | [Frankfurter API](https://frankfurter.dev) (ECB reference rates) | Free, no key, no rate limit hassle, backed by the European Central Bank | No |
| Economic calendar ("What to watch") | [ForexFactory calendar mirror](https://nfs.faireconomy.media/ff_calendar_thisweek.json) | Free, no key, widely used by small trading tools | No, but it's an unofficial/best-effort feed — see note below |
| Daily FX brief | Anthropic Claude (`claude-sonnet-5`) with web search | Turns current news into a short, plain-language, non-predictive summary | **Yes** — `ANTHROPIC_API_KEY` |

**Note on the economic calendar:** the ForexFactory mirror isn't an official, contractually supported API. The fetch
script (`scripts/fetch-events.mjs`) fails soft — if the feed is unreachable, it leaves the previous `events.json` in
place rather than breaking the section. If this feed disappears one day, that script is the only place to change.

## Architecture

This is a static site (Vite + React + TypeScript) with no backend server. All the "live" data is pre-fetched by
**GitHub Actions** into flat JSON files under `public/data/`, which the deployed site simply fetches at load time:

```
GitHub Actions (scheduled, 3x/day)
  → scripts/fetch-fx.mjs      → public/data/fx-history.json
  → scripts/fetch-events.mjs  → public/data/events.json
  → scripts/fetch-brief.mjs   → public/data/brief.json
  → commit changes back to main
      → push to main triggers the deploy workflow → GitHub Pages
```

This keeps the deployed app simple and fast (it's just static files + JSON), and — importantly — **keeps the
Anthropic API key server-side**. It only ever exists as a GitHub Actions secret on the runner that generates
`brief.json`; it is never sent to, or bundled into, the client-side JavaScript. If you look at the built app, there
is no API key anywhere in it.

Currency data (the whole point of this dashboard) does not depend on the AI brief at all. If `fetch-brief.mjs` fails
or the `ANTHROPIC_API_KEY` secret isn't set, it leaves the previous brief in place (or writes a clearly-labeled
"unavailable" placeholder) and exits successfully — the rest of the data-update job, and the whole site, keeps
working.

### Why fees are handled the way they are

The "market rate vs. Wise" toggle only changes figures about **how many EUR you actually receive right now** (the
calculator, and your logged conversions). It intentionally does *not* change the timing-comparison cards (You vs.
the 13th, Should I exchange today, HODL counter, Smart metrics) — Wise's fee applies about equally no matter which
day you convert on, so it mostly cancels out of "is today better than the 13th" questions. Keeping those cards on
the raw market rate keeps the timing analysis honest and comparable day to day.

Also, because Wise converts at the real mid-market rate rather than marking it up, the fee toggle deducts a
percentage + flat fee from the USD amount before conversion — it never touches the rate itself. That's different
from how a bank's "we'll give you our special rate" markup works, and is the whole reason Wise tends to be cheaper.

### Code structure

```
src/
  lib/
    types.ts          shared TypeScript types
    dates.ts           date helpers (all dates are ISO yyyy-mm-dd, compared as UTC calendar days)
    calculations.ts     pure functions: conversions, percentiles, benchmark/what-if logic, etc.
                         (no React, no formatting — fully unit-testable in isolation)
    format.ts           number/currency formatting only
    storage.ts           the localStorage-backed conversion log, behind a small interface
  context/
    DashboardContext.tsx fetches the JSON data once, holds the shared USD amount and fee settings
  components/           one component per dashboard section, all presentation — logic lives in lib/
```

## Running locally

```bash
npm install
npm run dev
```

The dev server reads `public/data/*.json` directly, so you'll see whatever was last committed there. To refresh it
with live data:

```bash
node scripts/fetch-fx.mjs
node scripts/fetch-events.mjs
ANTHROPIC_API_KEY=sk-... node scripts/fetch-brief.mjs   # optional — omit to leave the brief as-is
```

## Deploying to GitHub Pages

1. Push this repository to GitHub.
2. In **Settings → Pages**, set "Source" to **GitHub Actions**.
3. (Optional, for the AI brief) In **Settings → Secrets and variables → Actions**, add a repository secret named
   `ANTHROPIC_API_KEY`.
4. Push to `main` — `.github/workflows/deploy.yml` builds and deploys the site.
5. `.github/workflows/update-data.yml` runs on a schedule (and can be triggered manually from the Actions tab) to
   refresh the exchange-rate history, events calendar, and AI brief, committing any changes back to `main` — which
   in turn triggers a redeploy.

The build uses a relative Vite `base` (`./`), so it works at `https://<your-username>.github.io/<repo-name>/`
without any repo-name-specific configuration.

## Data storage & the multi-device limitation

Your manually logged conversions ("Was the headache worth it?") are stored in **localStorage**, entirely in your own
browser. This was a deliberate v1 choice to avoid unnecessary infrastructure — but it means:

- Victor's and Berta's entries do **not** sync with each other, or across devices for the same person.
- Clearing browser data / using a private window loses the log.

The storage layer is written behind a small `ConversionStore` interface (`src/lib/storage.ts`) specifically so it
can be swapped for a shared backend (e.g. [Supabase](https://supabase.com)'s free tier) later, without touching any
component code — implement the same interface against a real database and swap the one export.
